### 9.2 Reviewer gate (before anything goes live)
Spawn a fresh `general-purpose` reviewer per branch, using the brief in Appendix B.2.

What the reviewer does:
- Reads the full diff: `git -C <main> diff claude/master...nov26/<branch>`.
- Reads the tasks and the cited findings.
- Runs the 9.1 checks in the branch worktree on its reviewer port.
- Independently re-runs each finding's repro.
- Hunts for regressions, security issues, design-rule violations and silent catches.

Rules:
- The reviewer does not edit code.
- Verdict: **APPROVE** or **CHANGES REQUIRED**, with numbered must-fix items (severity and file:line)
  and optional nits.
- On CHANGES REQUIRED:
  1. Send the items to the implementer (SendMessage).
  2. The implementer fixes and commits.
  3. The same reviewer re-reviews the delta (SendMessage).
- Maximum 3 rounds. After that the orchestrator decides, and records the decision in Section 12.

### 9.3 Merge gate (orchestrator, per approved branch)
1. On `claude/master` in the main tree: `git merge --no-ff nov26/<branch>`. Conflicts:

2. On the merged tree, run in order:
   - `npm test`;
