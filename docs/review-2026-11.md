## 1. Verdict

**The engine room is excellent; the parts users touch are not yet trustworthy.**

- The core maths is exact. UK tax/NI/student loans matched an independent implementation across
  21,560 cases; US federal tax + FICA across 60,093 points; amortization, compounding and solvers to
  floating-point precision; every hub row reproduces. The July SEO restructure worked (69/69 one-hop
  301s, 52/52 anchors, clean canonicals/sitemap, 0 JSON-LD errors, doorway overlap down from 44-53%
  to a 22.7% maximum). Infra is solid (TTFB 68-156 ms, correct caching, CSP enforced, API fails closed).
  The file/dev tools' "never leaves your device" claim holds at the network level.
- But between the engine and the user there are defects that produce wrong answers for ordinary
  inputs: typing **"50,000" is read as 50** in every calculator; values typed before hydration are
  ignored; about **one in three hand-written figures in content is wrong** (~115 of ~340 recomputed);
  several calculators' own logic (rent-vs-buy, affordability, card payoff) lives untested inside
  components and is wrong; the site has been **unattended through a UK Budget, a Bank Rate rise and the
  IRS 2027 release**; and several things are **broken only in production** (blank 404s everywhere,
  HEIC conversion dead in Chrome/Edge/Firefox since March) because no test runs against production config.
- On traffic: the homepage shows a crawler-style renderer ~9% of its words; the strongest content is
  UK but every visitor defaults to USD/US framing; there is no 2027 content as the rollover starts;
  embeds earn no backlinks; there is no authority/distribution. None of this is fatal; most of it is cheap.

Raw finding count (before de-duplication): 27 S1, 86 S2, 118 S3, 38 S4 across 269 findings, plus
94 sub-findings in the CONTENT sub-reports. After de-duplication: **16 S1 items**, ~60 S2 items.

## 2. Systemic root causes (fix these and whole classes of findings disappear)

1. **Figures typed into markdown instead of generated from the engines.** The 4 computed hubs are
   exact; hand-written scenario/comparison/methodology/tool-copy figures are wrong ~1/3 of the time
   and silently age. -> Generate every published number at build time from `src/lib` (the hub pattern).
2. **Calculator logic inside `.tsx` components, untested.** Rent-vs-buy, affordability, credit-card
   payoff, net worth, investment-return time tab. The `src/lib` engines that ARE tested are exact.
   -> Move logic to `src/lib` with invariant tests ("identical paths -> 0 difference", "payment <= interest -> never").
3. **Tests run on the dev server, never on production config.** `_headers`, `_redirects`, 404
   handling and CSP are invisible to every test -> blank 404s and dead HEIC shipped unnoticed for months.
   -> One E2E job against `wrangler dev`/preview with `_headers` applied (the review harness already does this).
4. **One shared input component, one bug everywhere.** `SliderInput` parsing, controlled-input
   hydration, unguarded `localStorage` -> each defect hits all 23 calculators at once.
5. **Region is a display toggle that defaults to USD.** The deepest content is UK, but UK visitors get
   USD, US vocabulary, US partners and US-first related links until they find the selector.
6. **Freshness is only enforced at build time, and nothing rebuilds.** 4 months unattended: Budget
   28 Oct 2026, BoE 5 Nov 2026, IRS 5 Nov 2026 all moved facts the site states as current.
7. **Homepage built for spectacle, not task.** ~8 screens of cinematic intro before the first input,
   no nav/search during it, and it replays on internal "Home" clicks.
8. **Breadth over depth.** 46 tools in the hardest SERPs; the 23 file/dev tools carry many
   correctness defects (compressor enlarging files, Excel->PDF data loss, Markdown XSS).
